# 会議室予約バックエンド

### 必要要件:
- Golang 
- Sqlite3 (gccが必要であり、環境変数 CGO_ENABLED=1 を設定する必要があります)

### インストール


1. リポジトリをクローンします
````clone git@github.com:yaraya24/booking-room.git```rr

2. データベースをセットアップします 

```
sqlite3 ./booking_room.db < ./internal/db/setup-db.sql
```
3. その後、以下のコマンドでサーバーを実行できます 
```
go run cmd/main.go 
```

4. または、アプリを実行可能な実行ファイルとしてビルドすることもできます:
```
go build ./cmd
```

### 使い方

APIにアクセスするにはBasic認証を使用する必要があります。
ユーザーは setub-db.sql ファイルに記載されており、各ユーザーのパスワードは `password` です。
```
Jane:password
John:password
Sarah:password
```

予約を作成するには `POST localhost:8080/bookings` エンドポイントを使用します。
`room` と `date` を含むボディが必要で、日付は `YYYY/MM/DD` の形式である必要があります。

例:
```
{
	"date": "2024-10-10",
	"room": "D"
}
```

利用可能な部屋を確認するには `GET localhost:8080/bookings?{date}` にアクセスします。ここで date は `YYYY/MM/DD` の形式です。

## バグ・問題点
1. 存在しない部屋を予約できてしまうという、かなり深刻なバグがあります。これはアプリが予約を行う前に部屋が存在するかどうかをチェックしておらず、クライアントを盲目的に信頼しているためです（少し気づくのが遅れました）。

2. ユーザーがPOSTリクエストを行う際のバリデーションが不足しています。

3. データベースのセットアップにSQLファイルを使用することにしたため、パスワードをハッシュ化することができませんでした。現在は平文で保存されており、これは望ましくありません。

4. データベースに更新日時や作成日時などのメタカラムがありません。

5. データベースが実際に動作しているかを確認するためのpingを行っていません。

6. リクエストのロギング、リクエストID、レスポンスステータスなどを提供するミドルウェアを実装したかったのですが、時間がありませんでした。

7. 本格的な結合テストがありません。追加したのはリポジトリ層のテストのみです。これも時間の都合ですが、理想的にはJenkinsのようなものでスモークテストとして実施されるべきです。

## 改善点
1. Redisのようなキャッシュやインメモリキャッシュを追加して、アプリケーションのスケーラビリティを向上させると良かったと思います。特定の日付の利用可能な部屋を確認する際にLRUキャッシュのようなものを使用し、予約が発生した際にその日付を更新することができます。これはsqlite3が同時アクセスを許可しないという事実によってさらに重要になります。

2. データベースの改善。mySQLまたはPostgresへの移行を検討します。sqliteのパフォーマンスを向上させるためのオプションを設定することもできましたが、詳細に調べる時間がありませんでした。しかし、最終的には本番環境向けのデータベースが望ましいです。

3. セキュリティ・信頼性のために、サービスが過度または悪意のある使用から保護されるよう、レートリミッターもあると良いでしょう。
